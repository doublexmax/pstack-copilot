From idea to verified work

First, talk through the feature with Copilot. Agree on who it is for, what it should do, what is out of scope, and how to check the result.

Then hand the conversation to /steward. Steward keeps the outcome in view and directs poteto-worker subagents and poteto-mode sessions to build and verify the work.

You stay focused on the decisions that matter while the team works through the details. Steward checks the combined result against your goal, so verified code is less likely to solve the wrong problem.

For a single bounded task, you can also use /poteto-mode directly. Its playbooks cover investigation, bug fixes, features, review, performance, and longer runs.

pstack Copilot is an independent port of pstack for Cursor by poteto. It is MIT-licensed and adapted to Copilot, not a mirror of the Cursor plugin.

Custom addition to this port

Consistent supervision

Attach an independent, read-only verifier to any worker session. It checks factual claims and test or comparator edits against real repository state and session artifacts, and messages the worker only when primary evidence refutes a claim. It never writes the worker's code or prescribes fixes.

Read how independent supervision works in the README.

Custom addition to this port

Outcome alignment

Steward works above /poteto-mode, the core engineering layer. It gathers context, flags missing information or capability limits, and directs bounded pieces of work across repository and non-repository deliverables.

It checks the deliverables against the outcome you agreed on, rather than relying only on the workers' reports.

Read how outcome alignment works in the README.

Install pstack for GitHub Copilot

You need Git, Node.js, and the GitHub Copilot CLI with access to the models you select. The independent verifier also needs Python, with python on your PATH. In a POSIX shell, clone the project, register its skills, and copy its agents:

git clone https://github.com/doublexmax/pstack-copilot ~/.copilot/pstack
copilot skill add ~/.copilot/pstack/skills
mkdir -p ~/.copilot/agents
cp ~/.copilot/pstack/agents/*.agent.md ~/.copilot/agents/
copilot skill list

For always-on mode, run the installer. It updates your Copilot instructions, path trust, shell wrapper, and runtime hooks. It also installs the verifier's runtime extension. Preview the changes first if needed:

node ~/.copilot/pstack/scripts/install-always-on.mjs --dry-run
node ~/.copilot/pstack/scripts/install-always-on.mjs

Then start Copilot and run /setup-pstack to choose your models. See the setup guide for Windows, permissions, context policy, and uninstall instructions.

Try the workflow

Start a conversation in Copilot and work out the feature together:

Help me plan saved filters for the support dashboard.
Ask what users need, what should be in scope, and how we should verify it.
Don't implement anything yet.

Once you agree on the scope, hand the same conversation to Steward:

/steward use our discussion as the brief. Build saved filters and
verify that a saved filter survives a reload. Leave the changes for review.

Steward can divide the work among its workers, check what they deliver, and bring the result back to you.
