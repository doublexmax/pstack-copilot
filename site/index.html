Engineering playbooks, not just code generation

Start with a goal and a way to verify it. The /poteto-mode skill selects a playbook and coordinates the skills and agents needed for the task. Workflows cover investigation, bug fixes, feature development, code review, performance work, and longer autonomous runs.

Choose the models used for delegated work and review panels with /setup-pstack. The port also includes Azure DevOps pull request workflows in place of upstream's Graphite stacking and GitHub review flows.

pstack Copilot is an independent port of pstack for Cursor by poteto. It is MIT-licensed and adapted to Copilot, not a mirror of the Cursor plugin.

Custom addition to this port

Double checks your agent's claims

@doublexmax created Double for pstack-copilot. It is a custom addition, not available in upstream cursor/plugins pstack. Read the Double skill and supervisor agent for the full behavior.

Run /double inside the worker session, not a separate chat. It attaches a nested Double: <worker name> verifier session. Long unattended tasks in /poteto-mode attach Double automatically.

Double selects from your configured double verifier pool. It prefers a model with a different vendor family from the worker. It falls back to the first pool entry if none differs.

A local Python watcher waits at zero model tokens. The runtime extension wakes an idle Double session when the worker resumes. Verification turns spend model tokens.

Double checks factual claims and test or comparator edits against real repository state and session artifacts. It is a read-only supervisor. It never writes the worker's code or prescribes fixes.

Double messages the worker only when primary evidence refutes a claim. It stays silent on verified and unverified claims. Silence is not approval. Try Double in a worker session.

Install pstack for GitHub Copilot

You need Git, Node.js, and the GitHub Copilot CLI with access to the models you select. Double also needs Python, with python on your PATH. In a POSIX shell, clone the project, register its skills, and copy its agents:

git clone https://github.com/doublexmax/pstack-copilot ~/.copilot/pstack
copilot skill add ~/.copilot/pstack/skills
mkdir -p ~/.copilot/agents
cp ~/.copilot/pstack/agents/*.agent.md ~/.copilot/agents/
copilot skill list

For always-on mode, run the installer. It updates your Copilot instructions, path trust, shell wrapper, and runtime hooks. It also installs Double's runtime extension. Preview the changes first if needed:

node ~/.copilot/pstack/scripts/install-always-on.mjs --dry-run
node ~/.copilot/pstack/scripts/install-always-on.mjs

Then start Copilot and run /setup-pstack to choose your models. See the setup guide for Windows, permissions, context policy, and uninstall instructions.

Three tasks to try

Investigate and fix a bug

/poteto-mode the export writes duplicate rows when a retry lands mid-run.
Reproduce it first, fix the root cause, and verify the result.

Review a change before shipping

/poteto-mode review this PR for correctness and regressions.
Explain the evidence for each finding and what still needs verification.

Supervise a worker session

Run this inside the worker session, not a separate chat:

/double

Look for the nested Double: <worker name> session. It messages the worker only with evidence that refutes a claim. Silence is not approval, even when a claim remains unverified.

You do not need to name every skill or prescribe the delegation plan. Describe the outcome and what would prove it works.
